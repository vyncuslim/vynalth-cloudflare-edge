# Local workerd and production measurement boundary

The first isolated workerd run failed its timer/completeness validation; the failed report remains archived. The replacement uses the Node client monotonic clock, not a clock inside the Worker. It launches only a loopback listener with no cloud bindings or routes. Six fixed functional checks precede 900 ordinary measured loopback requests and 120 warmup requests. The synthetic origin always returns 204; no production endpoints are contacted. HTTP round-trip overhead and local scheduling are included. The report cannot qualify deployed inspection CPU latency. The native production invocation CPU metric measures the entire Worker. Obtain independent candidate-specific production profiling and coverage evidence before GA.

Content hardening: one capped buffer, a global structured-field budget, and a finite empty-chunk budget. Complete bounded JSON on previously reviewed routes can optionally be inspected without a declared length. Runtime opt-in `VYNALTH_WAF_UNFRAMED_CONTENT_ENABLED=true` is NOT set in production configuration; portable opt-in is explicit. Unknown routes, credentials, unsupported encodings and over-budget or incomplete bodies retain existing behavior. Existing schema contracts and original test corpus are unchanged. No broader rejection policy is introduced. Review runtime capacity and benign compatibility before enabling the opt-in in production.

References: https://developers.cloudflare.com/workers/runtime-apis/performance/ and https://developers.cloudflare.com/workers/observability/dev-tools/cpu-usage/. No GA release.
