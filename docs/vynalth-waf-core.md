# Vynalth WAF v1.1 - integrated pilot

All seven modules are implemented in the existing Worker, with explicit acceptance boundaries.
- Core: deterministic request rules plus bounded JSON structural observation on four exact routes. No prompt, password, email, upload, streaming body, arbitrary nested content, or raw payload logging. Unknown-length and compressed bodies are skipped. Heuristics never deny.
- Intelligence: locally observed rule evidence, repeat-burst classification, daily aggregate counts and SHA-256 evidence. No external reputation feed, AI attribution, or inference of identity from a source network.
- Identity: reuse only validated host-bound signed device credential; network counters use an HMAC of CF-attested IP, not a browser identity. No cross-site tracking or newly issued ID for risk. Existing global-device checks unchanged.
- Rate Shield: one globally serialized Durable Object per pseudonymous host/actor, separate explicit minute buckets. VWAF uses disjoint `vwaf:v1:` object names in the already-deployed SECURITY_DEVICE_RISK namespace, with isolated storage keys and protocol dispatch. Existing signed-device objects continue to use their legacy hex-only names and risk state. No new migration. IP and signed device counters supplement, not replace, existing per-colo limiters. Fixed window boundary bursts possible. Only selected public documents and expensive APIs; no origin bypass defense. Native per-colo state/event budgets bound load, but may drop observations and are not global quotas.
- Response: five distinct server-generated request IDs and at least three fixed hard-rule classes within 10 minutes produce a candidate; enforce mode restricts verified signed device for 72h with evidence persisted atomically. Network candidates are never automatically banned by this module; existing Cloudflare exact-IP containment remains separate. Device restrictions checked on scoped documents/expensive endpoints and hard probes, not every asset/API. Observations cannot silently turn into enforcement when mode changes.
- Evidence: private Durable Object ledger, max 128 recent records retained up to seven days, max 50 displayed, daily rule counts. Actor restriction evidence expires after seven days. Integrity digests are not immutable external evidence or proof of compromise. No raw IPs, paths, query/body, credentials or device IDs in ledger. No R2 mirror yet.
- Console: apex /__ops/vwaf read-only status with dedicated 43-128 character random URL-safe bearer secret VWAF_CONSOLE_TOKEN; no query tokens, no cross-site requests, no caching, no state writes. Existing temporary IP, global device and school policy guards retained. No credential => 404; no authenticated status until operator provisions secret.
- Alert: independent fixed ntfy.sh (authenticated dedicated private topic), Telegram and Axiom connectors with dedicated secrets VWAF_NTFY_TOPIC / VWAF_NTFY_TOKEN, VWAF_TELEGRAM_BOT_TOKEN / VWAF_TELEGRAM_CHAT_ID, VWAF_AXIOM_INGEST_TOKEN. Disabled by default. Global ledger reserves <=8 attempts per destination per rolling 24h, >=15min spacing, provider Retry-After; only acknowledged sends advance cursors. Aggregated privacy-safe digest, not every request; bounded retention may discard unsent detail. Existing notification channels untouched. Do not share existing provider quota or tokens without validating budgets and credential scope.

## Rollout
Initial Core and state modes observe, content enabled, console enabled but fail-closed without secret, external alerts disabled. Test build, shared-class protocol isolation and namespace compatibility before promotion; measure CPU, request/DO quotas, false positives and evidence loss. Existing Cloudflare WAF remains. No automatic plan upgrade. Separate switch to enforce after reviewed observation; state/binding failure cannot unblock a deterministic hard denial. No claim of full OWASP coverage or L3/L4 DDoS protection.

## Existing Telegram preservation

The original edge, GPS and honeypot notification paths and existing Telegram token/chat bindings remain unchanged. Existing alerts stay enabled; per-request notification of ordinary traffic stays disabled. VWAF alerts are additive, disabled by default, and require separate scoped credentials. Do not reuse or rotate existing Telegram credentials for this pilot.
