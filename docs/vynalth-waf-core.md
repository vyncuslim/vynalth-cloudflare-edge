# Vynalth WAF v1.2 — enforcement pilot and retired-console honeypot

- Core: deterministic hard rules now enforce on the two confirmed non-PHP pilot hosts. Extra private backups, system files and tool credentials; bounded path normalization; framing/template signals are observation-only. Public search, health, legitimate configuration and AI prompts are not blanket blocked. Bounded JSON metadata observation on two exact routes; no login/signup body inspection. This is not comprehensive OWASP body inspection.
- Intelligence: fixed rule IDs, score, per-request evidence and primary-category diversity. Core and content observations with the same request ID are retained separately. Scores are not proof of intrusion or attribution.
- Identity: validated host-bound signed device only; no fingerprinting, inferred human identity, new ID minting or cross-site tracking. Existing legacy and consent-linked policy checks unchanged. Signed device restrictions apply to ordinary API and HTML document requests, except recovery/legal/status, service relays, webhooks and public assets. Direct origin access remains outside this Worker.
- Rate Shield: exact per-actor rolling 60-second admission windows in existing Durable Objects. Denied attempts do not extend the window. Enforce existing reviewed DOC/IMAGE/SEARCH/SIGNUP categories; new LOGIN/CHAT categories remain observation-only. Network counters never create 72-hour bans. Per-colo admission budgets and supplemental fail-open state availability remain; no claim of global DDoS capacity.
- Response: five distinct hard-probe request IDs and three primary rule categories in 10 minutes; only a previously verified device receives a 72-hour restriction in enforcement mode. Observation-mode history is not promoted. No expiry extension on repeated hits. Restriction and canonical per-request evidence SHA-256 are stored atomically in actor DO. Private ledger bounded to 128 recent entries and seven days. Asynchronous R2 mirror for verified restrictions only: queue max 8, max 12 attempts/rolling day, 15-minute spacing, max 3 attempts per item, hash readback, idempotent content-addressed key. Queue saturation or delivery failure cannot silently imply archival; actor evidence remains. R2 prefix has no new automatic deletion or immutable object-lock guarantee. No raw IP, path, query, body, cookie, bearer token, or device ID is stored by these modules.
- Honeypot: permanently tombstone former apex VWAF console namespace, including descendants. Static 404, no forms, no credential reading, no upstream fetch, no public status API. Fixed category VWAF-501 only; one hit does not identify an attacker or cause a ban. The private DO status operation is internal only. A disabled honeypot still tombstones the namespace. Existing general PHP honeypots remain.
- Alert: existing Edge and GPS Telegram modules and flags retained, no token rotation. New independent VWAF external digest channels remain off until credentials and delivery budget are confirmed.
- Deployment: no new DO migration, route ownership change or plan upgrade. Existing private R2 bucket binding is used for bounded redacted incident records. Core and state modes enforce only the two pilot hosts; can switch off or observe without changing other security controls. Verify source, tests, version metadata, old bindings, public paths and privacy-safe event counts. Upstream WAF may prevent hard probes from reaching the Worker. No public malicious traffic is needed to test this change.

## v1.3 resilience upgrade

Deterministic core coverage expands to the ten explicitly reviewed non-PHP hosts already covered by the Cloudflare PHP rule and shared Worker routes. No wildcard enforcement, no honeypot or unrelated-domain scope expansion. Actor state, rate enforcement, and content inspection remain restricted to the original two hosts. Additional fixed private credentials and debug artifacts, inspection-only dot canonicalization, duplicate structured fields and local-destination advisory signals. Public configuration and AI prompt text remain untouched.

Identity: existing-only signed-cookie verification avoids minting on probes. Search uses the host-bound Edge credential. The apex uses a different canonical backend credential and intentionally disables Edge credential issuance; this module does not claim to validate or restrict that backend device credential. Existing origin/global-device controls remain. Device and network state calls are isolated; one timeout cannot suppress a successful independent denial. Content inspection happens after denial checks and has a separate per-colo admission key. State saturation remains supplemental fail-open behind existing Cloudflare/legacy enforcement. New login/chat counters remain observe-only.

Response: restriction evidence and bounded outbox committed together in the actor transaction. A retry alarm delivers the same redacted evidence to the private ledger (maximum three attempts with fifteen-minute spacing after the first scheduled attempt). Critical event admission is separate from routine telemetry, not a new global quota. Queue acceptance is distinct from R2 archival. Duplicate events can enqueue missed evidence without incrementing event counts; terminal archive failures cannot reset their attempt budget. R2 content-addressed evidence checks existing bytes and refuses overwrites, using conditional create and hash readback. Global archive limits remain unchanged. No public console, new secrets, device fingerprinting, plan upgrade, new migration or route ownership change. Existing Telegram notification code and flags unchanged. Actual production restriction/archival and notification delivery still require observed evidence.
